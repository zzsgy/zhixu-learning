# 知序电脑本地版

知序电脑本地版以 SQLite 作为主数据库，原始文档、提取正文、分类结果、全文索引和备份都保存在当前电脑。只有启用 DeepSeek 辅助分类或未来的 AI 追问时，相关文本才会发送给 DeepSeek。

## 第一次运行

1. 安装 Node.js 22.13 或更高版本。
2. 在本目录执行 `npm install`。
3. 双击 `start-zhixu.bat`。
4. 浏览器会自动打开 `http://127.0.0.1:47821`。

如果需要 DeepSeek 辅助分类：

1. 复制 `.env.example` 并命名为 `.env.local`。
2. 在 `.env.local` 的 `DEEPSEEK_API_KEY=` 后填写密钥。
3. 重新启动本地程序。

`.env.local` 已被 Git 忽略，不会提交到代码仓库。

## 本地数据位置

- 数据根目录默认为项目内的 `data/`，也可以用 `.env.local` 的 `ZHIXU_DATA_DIR` 整体迁移；当前电脑使用 `D:\ZhixuData\data`。
- `zhixu.db`：SQLite 主数据库。
- `attachments/`：上传的原始文件及视频生成的正式图文 PDF。
- `article-images/`：网页文章图片的本地缓存。
- `papers/`：已选论文的公开 PDF 本地缓存。
- `backups/`：每日 SQLite 备份，默认保留30天。

备份整个知识库时，请复制完整的 `data` 文件夹。不要只复制数据库而遗漏附件。

## 支持格式

- PDF：优先提取文本层；文本层为空或过少时自动进入本地 OCR 后台任务。
- 图片：PNG、JPG、WEBP、BMP、TIF 和 TIFF 作为扫描资料进入 OCR。
- Word：DOCX。
- Excel：XLSX。
- PowerPoint：PPTX。
- 文本：TXT、Markdown、HTML、JSON、CSV、XML、YAML、SQL及常见代码文件。

旧版 DOC、XLS、PPT 仍需转换为新格式；手写文字、公式和复杂表格不承诺自动识别正确。

## 本地 OCR

- OCR 使用本机 Tesseract，默认语言为 `chi_sim+eng`；扫描 PDF 使用本机 `pdftoppm` 先渲染逐页图片。
- Windows 安装完成后，可把工具加入 `PATH`，也可在 `.env.local` 配置 `ZHIXU_TESSERACT_PATH` 和 `ZHIXU_PDFTOPPM_PATH`。
- 图片和缺少有效文本层的 PDF 会自动进入 `document_ocr` 后台任务；上传接口不会等待整份扫描件识别完成。
- OCR 保存逐页正文、词语坐标、页级与总体置信度，并更新文档全文索引；原始图片或 PDF 始终保留。
- 文档阅读页显示识别状态、页数和总体置信度，可在失败或结果不理想时重新执行。
- 服务重启会恢复中断任务；工具未安装、语言包缺失、页面过多和识别超时都会保留明确失败原因。

## 自动分类

允许的一级分类为：

- AI
- 数据库
- 安全
- 程序
- 生物工程
- 工艺工程
- 其它

系统先执行本地关键词评分；配置 DeepSeek 后，会把文件名和最多约12000字符的正文节选发送给 DeepSeek校正分类。阅读页可随时手动修改分类。

## 文件夹与教程整站导入

- 文档库首页以树形文件夹作为主要入口；一级目录沿用 AI、数据库、生物工程等分类，文件夹内可以继续创建任意层级子目录。
- 每份文档或网页文章只有一个主要文件夹，标签仍在数据库中保留，用于搜索、相关推荐和跨主题组织。
- 已有资料升级后会自动进入对应的一级分类文件夹，不复制正文，也不影响收藏、阅读进度、批注和问答记录。
- 支持新建、重命名、移动和删除空文件夹；含有内容或子目录的文件夹不会被直接删除。
- 输入带 `#/` 路由的 Docsify 根链接时，系统会读取同源 `_sidebar.md`、验证章节并展示导入预览。
- 整站导入只读取同源 Markdown，不执行目标网站 JavaScript；404、正文过短和“规划中”章节会自动跳过。
- 同一教程再次导入时按原章节 URL 更新，不会产生重复文档。
- All-in-RAG 会自动保存到 `AI / RAG / All-in-RAG`，每个章节保持为独立文章，便于搜索、阅读和单章问答。

## 浏览器快速收藏与后台任务

- `browser-extension/` 提供本地 Chrome/Edge Manifest V3 扩展；在扩展管理页面启用开发者模式后，选择“加载已解压的扩展”并指向该目录。
- 在知序“本地数据”页面生成六位一次性配对码，再在扩展弹窗中输入；配对码十分钟内有效且只能使用一次。
- 扩展支持收藏当前网页、链接和选中文字。选区能够在清洗正文中精确定位时，会同时生成黄色高亮批注。
- 浏览器原始令牌只保存在扩展本地存储；SQLite 仅保存 SHA-256 摘要，可以随时在知序页面撤销客户端权限。
- 浏览器收藏采用 SQLite 持久化后台任务。服务异常退出后会恢复未完成任务，失败任务可在“本地数据”页面查看原因并重试。
- `import_jobs` 是 OCR、视频字幕和浏览器收藏共用的任务地基，页面统一显示排队、运行、完成和失败状态。

## 视频链接与字幕导入

- “导入”页面支持 YouTube、哔哩哔哩公开视频链接；点击整理按钮并确认后，后台任务会临时获取生成 PDF 所需的视频画面。
- 字幕按简体中文、繁体中文、英文顺序选择，人工字幕优先于自动字幕；导入正文保留每段起始时间，并可跳回原视频对应位置。
- 默认结果作为 PDF 文档保存，进入现有分类、文件夹、全文搜索、阅读工作台、批注和资料问答流程；旧版“仅保存链接”仍使用 `sourceType=video` 文章兼容。
- 视频入口默认执行“整理为图文 PDF 并保存”：优先读取公开字幕，再临时获取视频画面，筛选 PPT、流程图和演示界面，最后把 PDF 作为正式文档保存到文档库。
- 图文 PDF 会把字幕或语音转写、关键画面、画面 OCR 和对应时间段的讲解排在一起，并保留可跳回视频的时间戳。公开字幕存在时不会重复转写音频；没有独立字幕轨时才使用 faster-whisper 本地转写。
- yt-dlp 临时获取媒体，FFmpeg 提取所需音频和候选帧，Tesseract 识别画面文字，ReportLab 生成可搜索 PDF；成功、失败或服务异常重启后都会清理遗留视频、音频、截图和未入库 PDF。
- 知序不直接读取、导出或保存浏览器 Cookie，也不会绕过平台访问控制。已登录页面仍可用于人工确认视频状态；如果平台没有独立字幕轨，就使用上述本地转写方案。
- 大体积视频运行资产可通过 `ZHIXU_VIDEO_RUNTIME_DIR` 迁移；当前电脑使用 `D:\ZhixuData\video-runtime` 保存 FFmpeg、yt-dlp、Python 环境、Whisper 模型和临时任务文件。这些本机资产不进入 Git。
- 视频导入定向验证命令为 `npm run test:video`。

## 阅读工作台

- 文档、网页文章和论文共用一套本地阅读状态，可标记为“未读”“阅读中”或“已读完”。
- 页面会按滚动位置自动记录阅读百分比，再次打开时回到上次阅读位置。
- 结构化正文会自动生成章节目录；点击目录可在当前页面内跳转。
- 在正文中选中文字后，可以添加黄色、绿色、蓝色或红色高亮，并为高亮补充批注。
- 阅读工作台右侧提供独立笔记区，输入停止后自动写入 SQLite。
- 阅读字号和行距可以分别调整，偏好保存在当前浏览器中。
- 阅读状态、进度、笔记和高亮批注都只保存在本机数据库中。
- PDF 原版预览仍由浏览器内置阅读器呈现；需要高亮正文时，请切换到“清爽阅读”。

## 标签、专题与卡片复习

- 文档、网页文章和论文可以拥有多个标签，也可以同时加入多个学习专题。
- 统一搜索会检索文件、文章、论文和阅读笔记，并显示命中位置。
- 在阅读页选中一段原文后，可以制作概念、原理、对比、工程、问答、公式或故障卡片。
- 每张卡片保存来源类型、来源 ID、原文选区和字符锚点，卡片页可随时返回原始内容。
- 新卡片立即进入“今日复习”；完成“忘记、困难、记得、熟练”评价后，系统按结果安排下次复习。
- 文档库和论文库都提供永久删除入口，浏览器会先显示不可撤销的二次确认；删除来源会同时清理其阅读状态、批注、标签、专题关联和卡片。

## 英文网页文章翻译

- 网页导入后会根据正文识别中文、英文或中英混合内容；模型名、代码和英文缩写不会单独触发误判。
- 英文原文始终完整保存在 SQLite 中，重新翻译不会覆盖原文。
- 在文章阅读页点击“加入 Codex 翻译”后，文章才会进入本地队列，不会自动把内容发送给 DeepSeek 或第三方翻译服务。
- Codex 使用 `node --disable-warning=ExperimentalWarning scripts/article-translation-queue.mjs list` 读取用户主动加入的文章。
- Codex 按 `{ "translations": [{ "articleId": "...", "translatedTitle": "...", "translatedSummary": "...", "translatedHtml": "..." }] }` 写入临时 JSON，再运行 `node --disable-warning=ExperimentalWarning scripts/article-translation-queue.mjs apply <json-file>` 写回 SQLite。
- `translatedHtml` 只允许无属性的 `h2、h3、h4、p、ul、ol、li、blockquote、pre、code、table、thead、tbody、tr、th、td、strong、em、sub、sup` 标签；公式、代码、表格数值、模型名和必要英文术语必须保留。
- 长文章按语义章节分段翻译后合并，不设置最高字数限制；完成后可在中文译文、英文原文和双语对照之间切换。

## 每周论文库

- 程序启动时检查当前自然周是否已经准备候选论文，运行期间每六小时再次检查。
- 网页打开期间每小时检查一次提醒状态；本周尚未选择时会弹出候选窗口。
- 候选论文来自 arXiv 公开索引，覆盖 AI、生物工程、工艺工程和数据库。
- 原始英文标题和摘要完整保留；页面优先展示 Codex 生成的中文标题与中文摘要。
- 论文卡片把“中文阅读”“arXiv/论文原文”和“英文 PDF”分成独立入口。
- 用户选择或手动导入英文论文后，服务先缓存 PDF、提取正文并立即加入后台 Codex 全文翻译队列；上传接口不会等待长时间翻译。
- 本地工作器同一时间只翻译一篇，页面显示排队中、翻译中、已完成或失败，并在完成后自动刷新中文全文。
- 自动全文翻译需要先在 PowerShell 运行 `codex login` 完成本机 Codex CLI 登录；未登录时论文会留在队列中，每分钟自动重试可用性检查，不会改用 DeepSeek 或第三方翻译服务。
- 可在 `.env.local` 使用 `ZHIXU_CODEX_MODEL=` 覆盖全文翻译模型；留空时使用 Codex CLI 默认模型。
- 中文全文采用站内独立阅读页，保留方法、公式、实验、结论和附录，不设最高字数限制。
- “同步李沐精读”会从 `mli/paper-reading` 公开目录导入已录制条目，并把论文链接、Bilibili/YouTube 视频、时长和中文阅读提示保存在本地。
- 论文库可按“每周精选”和“李沐精读”筛选。
- 自动弹出选择窗口前，会等待本周候选完成 Codex 中文翻译。
- 选择“明天再提醒”会延后24小时；选择“本周不选”后，下个自然周再提醒。
- 每周最多正式选入一篇论文，只有确认选择的论文会保存进本地 SQLite。
- 候选元数据更新需要联网；网络不可用不会影响文档库和已有论文的本地阅读。
- 后台全文翻译需要电脑保持开机、知序服务正在运行并且 Codex CLI 已登录。

## 后台运行与自动恢复

- 双击 `start-zhixu.bat` 后，知序由 `service-runner.mjs` 在后台运行；关闭启动窗口不会再终止服务。
- 守护进程会在 Node.js 服务异常退出后自动重启，并采用最长30秒的退避间隔，避免故障时高频循环。
- 普通日志写入 `work/zhixu-service.log`，错误日志写入 `work/zhixu-service-error.log`。
- 首次安装登录自启动：在 PowerShell 中运行 `powershell -ExecutionPolicy Bypass -File scripts/install-autostart.ps1`。
- 如需移除登录自启动：运行 `powershell -ExecutionPolicy Bypass -File scripts/uninstall-autostart.ps1`。
- 电脑关机期间本地网站无法访问；重新登录 Windows 后，计划任务会自动恢复服务。
- 浏览器扩展只能在知序服务运行期间提交收藏；任务一旦写入 SQLite，服务重启后可以继续处理。

## 从云端迁移

当前本地版不会自动删除或修改原 Cloudflare D1 数据。先从原网站导出完整 JSON，保留为迁移备份。下一阶段可以根据该 JSON 的实际结构导入本地 SQLite，完成卡片、文章、批注和专题的迁移。

## 安全说明

- 服务默认只监听 `127.0.0.1`，同一局域网中的其它设备也不能直接访问。
- 上传容量默认每个文件最大200MB，可在 `.env.local` 调整。
- 不要将 `data/` 或 `.env.local` 提交到 GitHub。
- 电脑磁盘损坏仍可能造成主库和同盘备份同时丢失，建议定期把 `data/backups` 和 `data/attachments` 复制到另一块磁盘。
